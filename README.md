# 捏捏实验室（Godot Web 原型）

这是一个 Godot 4.7 的 Web 捏捏原型，当前加载 `glb/sfl.glb` 正式月饼模型。按压产生局部凹陷，拖动产生大范围拉长与横向收缩，松手后阻尼弹簧恢复形状。

## 运行与操作

- 使用 Godot 4.7 打开 `project.godot`，按 F5 运行。
- 鼠标左键或单指按住、拖动模型：仅按压 / 推揉，凹陷平滑跟随。按住约 1.5 秒逐渐压到最大深度，同时整体轻微压扁、向两侧扩展。
- 电脑端仅 Shift + 左键拖动触发拉伸；松开 Shift 停止拉伸，右键不触发拉伸。
- 触屏在模型上放下两指并向外分开：拉伸。两指一起平移不拉伸，任意一指抬起后恢复单指按压。
- 拉出模型轮廓后仍可继续拖动；支持上下、左右方向。
- 松开后自动回弹；拖动空白处旋转模型。
- 左上角“参数”调整按压深度、手指宽度、柔软度、回弹和拉伸。
- 镜头随拉伸幅度退让；“镜头后退”设为 0 可关闭。

## Web 导出

1. 在 Godot 的“项目 > 导出”中确认已安装对应版本的 Web Export Templates。
2. 选择 `Web` 预设并导出。预设输出路径是 `output/web/nienie.html`。
3. 将导出的整个 `output/web/` 目录部署到支持静态文件的 HTTPS 网站，或用本地 HTTP 服务器预览。不要用 `file://` 直接打开 HTML；浏览器需要通过 HTTP(S) 加载 WASM、PCK 和工作线程文件。

导出预设位于 `export_presets.cfg`。浏览器部署需提供 Godot Web 导出所需的 MIME 类型；启用线程导出时还需服务器设置 COOP/COEP 跨源隔离响应头。本项目默认关闭线程支持，通常不需要这组隔离头。

## 目录与文件

```text
.
├── project.godot           # 项目入口、窗口尺寸、输入与渲染/物理设置
├── export_presets.cfg      # Web 平台导出预设和导出目标
├── icon.svg                # Godot 项目图标
├── scenes/
│   └── main.tscn            # 主场景；挂载主控制脚本
├── scripts/
│   ├── main.gd              # 场景搭建、镜头灯光、输入拾取和 HUD
│   ├── blob_deformer.gd     # 网格拾取、弹簧形变场和法线更新
│   └── doodle_canvas.gd     # 涂鸦纹理、画笔与橡皮擦
└── output/web/              # Web 导出产物（HTML/JS/WASM/PCK）
```

`.godot/` 是编辑器导入缓存，`.uid` 是 Godot 脚本资源标识；它们由 Godot 管理，不是手写的游戏逻辑。`output/web/` 中若已有导出文件，它们是构建产物，重新导出会覆盖对应文件。

## 形变实现

1. **真实表面拾取**：按下时射线与当前变形后的三角面相交，返回命中位置、静止形状中的重心插值位置和法线。计算先按模型半径归一化，避免小尺寸 GLB 受几何精度阈值影响。旧碰撞体不再参与交互拾取。
2. **稳定拖拽**：按压拖动使用静止表面的原生 TriangleMesh BVH，冻结交互相机投影，不追逐变形中的凹面；接触位置和法线以约 45ms 时间常数平滑跟随。系统输入合并为每个物理帧最多一次查询。拉伸使用经过命中点、平行台面的水平面；前后和左右拖动都保持在 XZ 平面，避免俯视镜头把前向拖动映射成向下拉。
3. **按压**：接触法线方向下陷，切平面高斯权重形成碗状凹陷，外围轻微隆起。按住时长通过 smoothstep 渐进增加深度，`press_duration` 默认 1.5 秒，拖动不重置计时。`squash_strength` 默认 0.10，以底面为基准轻微压扁，并横向扩展。最大深度有上限。底部采用平滑压缩，保留至少原始局部高度的 15%，不再把上下面硬压到同一高度。拉伸厚度以底面为基准变化，模型与底座保留最长边 0.15% 的微小间隙，减少深度冲突。
4. **拉伸**：大范围沿拖动方向伸长，垂直方向按伸长倍率平方根的倒数收缩，叠加宽范围的抓取权重。大幅拉伸时应变逐渐集中到中段，形成中间细、两端宽的收腰；横截面比例保留至少 16%，不会主动断开。拉伸上限按模型半径计量。该收缩是视觉近似，不是完整体积约束。
5. **回弹**：对形变场的强度和拉伸向量积分，使用最多 1/120 秒的子步。拉伸释放时固定原拉伸轴并保留正负位移：正向变长变薄，负向越过原形后变短变厚。拉伸采用较低阻尼，`recovery_time` 内约三个振荡周期，各次回弹逐渐衰减；释放时实际拉伸越长，回弹越强。负向压缩倍率保持正值，避免模型翻转。相同位置始终得到相同位移，避免独立顶点弹簧撕开 UV 接缝。重新抓取时保留回弹状态，按压接触位置及时更新。静止后停止计算。
6. **渲染**：静态网格配合 `shaders/soft_deformation.gdshader`，GPU 计算顶点形变和有限差分法线。逐帧 CPU 只更新弹簧和 uniform，不再重建网格或上传全部顶点。保留本项目模型的底色贴图、颜色、粗糙度、金属度和法线贴图；形变时同时变换法线贴图的切线基。首次／重新抓取才按需生成当前形状的 CPU 拾取数据；拖动期间复用静止表面 BVH。GPU 与按需 CPU 求值采用相同形变公式。

主要文件：`scripts/main.gd` 负责输入、相机和 HUD；`scripts/blob_deformer.gd` 负责拾取和弹簧状态；`shaders/soft_deformation.gdshader` 负责 GPU 形变和法线。

当前支持单指按压、双指拉伸和模型的第一个 MeshInstance / surface；正式月饼模型为单网格、单 surface（5,925 个顶点）。加载时将 GLB 节点的旋转、缩放烘焙到顶点、法线和切线，统一为直立坐标，再按最长边归一化、保留建模师设置的原点和水平位置，只调整高度放在底座上。没有自碰撞、刚体交互或严格体积保持。复杂多部件模型的大幅形变仍可能出现局部穿插，移动浏览器性能需要在目标设备上实测。


验证真实模型拾取、鼠标及触屏事件、轮廓外拖动、竖直拉伸、GUI 捕获、镜头稳定性、回弹和参数极值。图形环境可追加 `-- --capture`，保存静止、按压、拉伸和恢复截图到 `/tmp/nienie-*.png`。

### 性能对比

本机 Apple M4、Godot 4.7.2 headless，每项 120 次采样的 CPU 中位耗时（不是手机 FPS，也不包含 GPU 绘制）：

| 工作 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 按压状态更新 | 3.550 ms | 约 0.001 ms |
| 拖动输入及拾取 | 0.962 ms | 0.009 ms |
| 拉伸状态更新 | 5.719 ms | 约 0.001 ms |

首次抓取／重新抓取仍有一次 CPU 形状求值和 BVH 建立成本。手机浏览器 GPU 帧耗时及触摸延迟需要真机验证。

### 按压轨迹与边缘过渡

默认手指宽度从 0.23 缩小 40% 至 0.138，参数面板同步调整。每次按压沿用触下时的法线方向，避免顶部与侧面法线切换导致突然塌陷。当前接触位置在本次物理更新中直接跟随拾取点，不再按半径限速或缓慢追赶；触下立即施加基础压力，继续按住仍会逐渐加深。

拖动轨迹采用连续线段的扫掠凹槽，保留 12 段常规轨迹和最多 8 段渐隐轨迹，直线拖动合并延长，转弯新增线段。沿线段插值两端深度并按回弹时长指数衰减，消除独立圆坑叠成的分节外观；不同按压手势不连接。使用按形变强度加权的连续归一化混合，避免硬切换造成法线亮点，也不累加压深。凹坑深度同时受参数、模型在按压方向的厚度 45% 和接触半径 1.5 倍限制。整体压缩采用独立的 0.25 秒时间常数渐进跟随，触下基础压力只立即作用于局部凹坑。历史轨迹与当前凹陷使用相同 GPU 和 CPU 公式，全部恢复后停止更新。容量满后旧轨迹进入渐隐槽位，在回弹时长的 35% 内平滑淡出，完全消失后才删除；新增转弯段按回弹时长的 1/16 节流，当前接触点仍逐帧跟手。轨迹增加 GPU 顶点计算，目标手机仍需真机评估。

恢复末段按每个求值位置的局部最大位移归一化混合权重，避免远处仍在按压的强接触点影响旧痕迹消退。历史轨迹不再按单独强度阈值停算；按压和轨迹强度都低于 0.00001 后才整体清理。

### 粉色柔光场景

游戏以720×1280为竖屏基准，使用 `window/stretch/aspect="keep_width"` 等比适配窗口。手机长屏保持720逻辑宽度，高度随浏览器可用区域扩展，UI上下锚点随之布局，不强制锁定9:16；横屏或宽窗口保持基准竖屏画面并居中留边，不横向拉伸。这是画面布局约束，不依赖浏览器是否支持强制锁定设备方向。

所有产品共用一套灯光：左上主光能量 0.42（投影）、前方补光 0.12（无投影），中性环境光 0.24。切换产品不改变灯光。`scripts/model_profiles.gd` 的 `MATERIAL_PROFILES` 单独校准舒芙蕾、大福、豆腐的粗糙度、高光和法线强度，不修改 GLB 原始材质、底色贴图或涂鸦颜色；枫叶（fy.glb）暂不配置，沿用导入材质参数。新增模型可在此表添加配置，无需单独打光。形变 Shader 显式接入高光参数，移动端形变法线算法保持不变。

`shaders/pink_backdrop.gdshader` 在地面上绘制浅粉渐变、奶白椭圆柔光及底座接触阴影；背景不受模型灯光影响，不使用实时反射或额外阴影贴图。柔光固定在画面中，接触阴影使用世界坐标并跟随底座尺寸。底座保留 bottom.glb 原有材质与木纹颜色，不额外提亮。相机以约 60° 仰角俯视模型，左上方主光配合弱补光，使投影落向画面右下方；月饼保留形变材质。背景使用 unshaded 保持移动 Web 上的稳定外观。

拉伸渲染优化：法线与法线贴图共用切线方向的有限差分采样，完整形变求值由每顶点 5 次降至 3 次（使用法线贴图时），保持切线手性；拉伸倍率、收腰强度和轴向范围在 CPU 每帧计算后上传。无按压时跳过当前凹坑的指数计算。压缩回弹的高度膨胀幅度增强为原增量的 1.75 倍，厚度以底面为基准向上变化，并乘以 X/Z 两方向的余弦平方包络：中心最高、边缘回到原高度，边缘斜率为零，避免整体一起拔高。GPU 实际帧率需要目标手机实测。

### 按压手感切换

参数面板中的“按压收拢与翘边”开关默认开启：中心凹陷、周围材料沿切平面向按压点收拢，侧缘平滑向上卷成圆弧，随按压强度及轨迹恢复变化；关闭使用原版高斯碗状按压公式。代码默认值由 `scripts/blob_deformer.gd` 的 `DEFAULT_RAISED_RIM_PRESS` 控制。切换时结束当前手势并清除残余形变，防止已有轨迹突然改变轮廓。新模式是收拢与侧边弯曲的视觉近似，不是严格体积守恒求解；沿用原深度限制和底面保护。CPU 拾取镜像与 GPU 使用相同轮廓。

收拢模式的拖尾恢复时间为原版的 30%，松手后局部按压弹簧恢复也加快；拉伸振荡周期与原版拖尾保持不变。

双指拉伸在开始时记录两个材料接触点，并分别施加浅凹陷；抓取压力渐进建立，松手后衰减。Shift 鼠标拉伸使用鼠标抓点及其对侧支撑点。接触凹坑沿用原底面保护，重叠时只取较强凹陷避免加倍压深，拉伸期间无需逐帧重新拾取。

按压释放附加小幅方向回弹：沿最后按压拖动的水平轴，原地按压默认模型 X 轴，以速度脉冲启动缩短增厚，再反向回摆并衰减。幅度随释放时压力增强，两种按压模式均生效；沿用拉伸的底面固定增厚与中心隆起公式，不改变拉伸释放参数。


## 涂鸦

### 操作与选色

游戏页底部切换「捏捏／涂鸦」，编辑工具位于底部面板。三个标签分别为涂鸦、贴纸、橡皮擦；涂鸦与橡皮擦有独立的小中大笔刷。画笔使用8色预设色盘。空白处拖动仍可旋转模型；清除需要在橡皮擦页确认。具体场景与历史说明见下面。

笔迹退出涂鸦后保留并随形变变化；透明度混合仍由底层笔刷支持，新面板目前不提供旧版RGBA滑条、缩放条和眼睛按钮。

### 实现与性能

- `scripts/main.gd`：绘制输入、工具栏、精简选色器、相机缩放与角度切换、退出视角过渡。
- `scripts/blob_deformer.gd`：三角形射线拾取，通过重心坐标插值得到命中表面的 UV，并绑定涂鸦纹理。
- `scripts/doodle_canvas.gd`：1024×1024 独立 RGBA `ImageTexture`，实现笔刷颜色混合、局部擦除和清空。
- `shaders/soft_deformation.gdshader`：按 UV 将涂鸦颜色叠加到原材质上，笔迹随网格一起形变。

拖动沿屏幕路径采样，不直接连接 UV 坐标，避免跨 UV 岛产生错误连线。绘制时复用静止表面 BVH，不逐笔重建模型网格；只在涂鸦发生变化时，每个渲染帧最多上传一次纹理。

所有笔迹合并到同一张纹理，不按笔画数量增加模型或绘制对象，因此已有笔迹数量不会持续增加显示开销。单张 RGBA8 像素数据约 4 MiB，CPU 图像与 GPU 纹理分别占用内存，实际总占用还包含运行时开销。绘制时的主要成本是射线拾取、笔刷覆盖像素计算和纹理更新；较粗笔刷及快速拖动会增加计算量。尚未进行手机真机帧率验证。

### 编辑页面与图片贴纸

游戏页底部「涂鸦」进入 `scenes/edit.tscn`（`game.tscn` 子场景），保留底部模式切换。编辑页顶部以撤销/重做替代声音按钮，没有可用步骤时置灰。涂鸦与橡皮擦分别记忆小/中/大笔刷（半径5/15/24纹理像素）；画笔提供8个颜色。橡皮擦页点击清空会打开独立的 `scenes/confirm.tscn`，确认才清除。

贴纸页列出 `res/ui/edit/stickers/` 的59张PNG；选择后在模型上点击/拖动放置预览，滑条控制尺寸和旋转，点击确认提交，未确认时可用顶部撤销取消预览。不是多层贴纸管理器。

撤销/重做涵盖完整笔画、擦除、确认贴纸及清空。历史用无损压缩快照，最多20步、32 MiB历史预算；新操作清除重做分支，模型切换重置历史。预览不占历史步骤。绘图仍写入同一张1024×1024 UV纹理，随模型形变。暂不实现作品存档。

贴纸第一版表面投射验证由 `scripts/sticker_projector.gd` 实现：在静止模型表面建立投射平面，放置与拖动时均按当前相机上方重新校正朝向，不累积曲面移动带来的旋转；贴纸的主动旋转仅由角度滑条控制，尺寸按模型最长边比例计算，不再受各 UV 岛旋转、镜像及比例影响。每个模型首次放置缓存三角形空间网格，仅查询投射盒附近的面；裁剪后逐三角形烘焙 UV 区域，补一像素接缝边缘，恢复上一次预览足迹，不重复合成透明度。投射深度为贴纸宽度的30%，排除法线偏离投射方向超过约66°的面，避免背面穿透及在陡峭转角过度拉长。预览限制为20次/秒，鼠标/手指松开及确认时强制补齐最终结果。确认后无额外贴纸网格或绘制调用。极端曲面可能裁切；重叠 UV 仍会重复显示，需要模型提供不重叠的 UV。桌面测试不代表手机 Web 性能，需用默认及最大尺寸在真机验证。

界面测试：`Godot --headless --path . --script tests/edit_screen_test.gd`；去掉headless并加 `-- --capture` 可生成三种工具的截图。

### 当前限制

当前只维护本次运行中的一张涂鸦层，退出绘制模式不会丢失，重新启动游戏后清空。**保存功能暂不实现**；当前没有多作品存档、恢复或存档选择预览。

笔宽使用 UV 纹理像素单位，不同 UV 密度区域的实际线宽可能不同。重叠 UV 的区域会共享笔迹，正式模型应提供不重叠的 UV。

涂鸦相关回归验证包含鼠标与模拟触摸绘制、UV 落笔、颜色覆盖、不透明度、局部擦除、工具粗细独立记忆、缩放与视角切换、淡化后的输入穿透，以及退出视角过渡。运行方式见上方「验证」；图形测试可生成 `/tmp/nienie-doodle-*.png` 截图。

## 参数弹窗

「参数」入口打开带半透明背景的全屏弹窗，点击内容区外背景或右上角「关闭」即可关闭，内容支持滚动。参数文字已放大加粗，滑动条、拖动圆点和开关使用放大样式。此弹窗用于形变参数调整，与涂鸦模式的两侧工具栏分开。


手机触摸输入：`project.godot` 开启 `pointing/emulate_mouse_from_touch`，让 Godot 原生滑条、选色区及 RGBA 通道响应触摸拖动。模型交互在 `_input` 与 `_unhandled_input` 中跳过 `InputEvent.DEVICE_ID_EMULATION` 的鼠标事件，继续使用真实触摸 ID 处理按压、双指拉伸及绘制，避免同一触摸被重复处理。修改此设置后需重新导出并更新 Web 产物。


### 移动浏览器加载与双指手势

Web 导出使用 `web/shell.html` 自定义页面，保持单线程导出。由于当前不实现存档，启动配置的 `persistentPaths` 为空，不等待 IndexedDB 持久化初始化。加载页显示下载进度与初始化状态，45 秒无进度更新时提供提示及重新加载按钮；超时提示不会取消仍在进行的加载。

画布显式设置 `touch-action: none`，并用非 passive 监听器阻止 `touchstart`、`touchmove` 和 iOS `gesture*` 的浏览器默认手势，不阻止事件传播，仍由 Godot 处理 UI 触摸和模型双指拉伸。第二指落下时，两个接触点均使用稳定表面拾取，避免第一指造成的凹坑干扰命中。

这些处理尚未在夸克真机上验证。若仍卡加载，应记录加载提示、设备和浏览器版本，并检查服务器 WASM/PCK 请求、压缩与缓存；不支持 WebGL 2 / 所需 WebAssembly 能力的内核无法仅靠页面脚本兼容。部署时完整替换同一次导出的 Web 文件，避免旧 HTML/JS 与新 WASM/PCK 混用。


## 按钮握压

非涂鸦模式下，底部中央显示「按住挤压」按钮。按住后约 0.6–0.9 秒逐渐握紧并保持，松开后连续恢复，伴随小幅衰减回弹；中途松开或再次按住都沿用当前强度，不从头跳变。涂鸦模式隐藏并取消握压，失去应用焦点时释放握压。

握压采用 `soft_deformation.gdshader` 中的独立形变场：整个模型平滑升离木板，最大抬升高度为模型半径的 1.8 倍，镜头转向 75° 俯视并跟随模型抬高。挤压保持屏幕左右握持，左侧四指接触带斜向排列，右上方增加宽圆、斜向的大拇指凹痕，接触中心位于四指手宽上沿之外（手宽半径的 1.10–1.20 倍），长轴和短轴分别为手宽半径的 1.02、0.48 倍。极限顶面下陷深度系数从模型厚度的 0.26 提至 0.46，印记延伸到上端鼓包，独立于四指接触带。随着握紧，拇指接触点向中心移动，斜角从约 15° 增至 35°；上下两端反向侧倾，并叠加掌心剪切，产生局部扭曲。端部横向与厚度鼓包较旧版减弱，避免对称的哑铃形轮廓。形变及接触凹痕均由 GPU 顶点位移实现，有限差分法线提供光影，涂鸦 UV 和原材质保留。

固定手宽按原始模型较短平面尺寸的 54% 标定（`GRIP_HAND_SPAN_RATIO`），不随朝向投影长度或拉伸长度缩放。接触带逐渐倾斜但不展开，四指保持固定间距。模型预先旋转后仍使用相机右方向转换的局部握压轴。CPU/GPU 使用同一套形变公式。

参考四张力度递增的照片，用 `_grip_pose_parameters()` 定义四个关键姿态。下表为动画调节权重，每列的 100% 是本列最大效果，不是模型尺寸变化比例，也不是照片实测物理量。

| 力度进度 | 中部收窄/压薄 | 两端鼓出 | 指腹/拇指压入 | 扭转/剪切 |
| --- | --- | --- | --- | --- |
| 25%，轻握 | 32% | 10% | 18% | 2% |
| 50%，中握 | 57% | 25% | 36% | 12% |
| 75%，重握 | 84% | 63% | 78% | 60% |
| 100%，极限 | 100% | 100% | 100% | 100% |

各通道在关键姿态间分别用平滑曲线插值，体现先接触、再压入、后堆积扭转的顺序，松手时连续回弹，回弹越过原状时停用接触凹痕。接近极限（握紧进度 94% 以上）时沿屏幕横向播放随机幅度和周期的平滑抖动，同时沿画面上下方向叠加主抖动幅度 20%–35% 的微抖，每轮随机相位，避免固定斜线往返。两轴在周期端点平滑归零，松手后一同快速衰减。振动与模型抖动共用周期，每轮随机 0.10–0.18 秒的抖动开始时只触发一次，不再独立高频调用；Web 每次固定 1 毫秒单脉冲（实际时长可能被设备调整），原生仍为 8–18 毫秒且强度上限为 0.18，不支持的浏览器静默跳过；松手或取消立即停止振动。握压及回弹期间拦截按压、拉伸、模型旋转，松手后悬空高度与相机视角平滑恢复。

CPU 积分握压强度弹簧，并更新独立升降进度和相机姿态；CPU 每帧额外插值一个四维姿态参数传入 GPU，GPU 使用平滑接触场、局部侧倾和剪切计算轮廓，沿用原有限差分法线。渲染无需逐帧重建网格或拾取 BVH，CPU 形状仅在查询时按相同公式求值。该效果是固定视觉动画，不是手部碰撞或严格体积守恒模拟，手机真机性能仍需验证。


## 按钮扭转

底部「按住扭转」与挤压并列，涂鸦时隐藏。长按沿用挤压的抬升、75° 视角、弹簧进度和松手回弹，极限时同样随机左右/轻微上下抖动并同步振动。两种动作互斥，动作和回弹期间禁止按压、拉伸、旋转。每次扭转随机选择正负方向，两端各反向扭约 105°（两端相对约 210°），中部轻微收紧并延展，两端径向鼓起；沿轴叠加连续螺旋褶皱（主褶皱、局部次级褶皱和细纹三层叠加；不同走向、深浅与弯曲，轴向间距在中央收紧，两端更宽大、中央更小更密），随握紧非线性加深、随扭转方向反向，空间纹理固定，不随帧随机变化，端点平滑淡出，松手后随回弹消退。沿用有限差分法线显示真实沟槽光影。采用 GPU 顶点形变，CPU 查询保持相同公式。

扭转轴绑定模型局部坐标，不随相机或模型在场景中的旋转改变。`BlobDeformer.twist_axis_local` 可为不同模型指定轴；默认零向量自动选择原始 X/Z 平面中较长的轴作为旋转轴，让长向两端的短边反向拧动（不是绕短轴拧长边）。沿轴的局部坐标决定每个顶点的扭角，不产生手部模型或逐帧网格上传。


### 移动端形变光照

形变法线使用与 UV 无关的几何切平面采样，避免镜像 UV 两侧采用不同采样方向；差分先除以采样间距，再做叉乘与归一化，降低小数值在移动 GPU 上下溢的风险。法线贴图切线通过同一组导数变换，重新正交化并保留镜像 UV 的手性。仍为两次差分采样，没有增加形变场求值次数。桌面回归通过；手机出现的整块明暗断层是否完全消除，需在原设备浏览器重新加载完整新版导出包验证。


### 移动端首次拉伸光照修正

针对「首次拉伸、涂鸦清理后拉伸异常，按压后恢复」路径，零力度按压场始终计算。启动和重置均初始化接触点、法线、抓取点、恢复轴；零拉伸方向使用有效默认轴；交互开始后立即上传接触参数。保持零按压力度，不通过伪造按压来预热。首次和退出涂鸦后的直接拉伸保留回归测试。用户在原小米设备复测反馈按压、拉伸均未再出现错乱阴影，临时阴影诊断 UI 和测试分支已移除，光影与网格质量保留。


## 场景拍照与分享

点击右上「拍照」，使用一次性 SubViewport 共享当前 3D 世界、复制相机视角，仅渲染模型、木板、灯光和背景，保留涂鸦；不包含任何 CanvasLayer 操作按钮或弹窗。不会通过短暂隐藏 UI 截图，因此不会产生 UI 闪烁。生成期间及预览弹窗中阻止模型手势，关闭后恢复交互。

照片为 JPEG（质量 0.93），网页按浏览器可视区域尺寸 × devicePixelRatio、桌面按窗口像素尺寸生成，最长边限制 4096 并保持比例，避免超大设备产生过高瞬时内存/渲染成本。预览使用最长边 960 的缩略图，保存使用原尺寸 JPEG；文件名包含拍照时间。独立视口仅生成照片时渲染一次，随后销毁，关闭弹窗释放照片和网页 Blob URL。

截图弹窗为可编辑的 `scenes/photo.tscn`，图片位于 `res/ui/photo/`。包含缩略图、保存、取消，以及按 X → LINE → Instagram → TikTok → Kakao 排列的横向分享列表，支持鼠标拖动、手指滑动和滚轮，滑动不触发分享。X 直接打开网页发布入口并预填文字和当前游戏链接；LINE 直接打开链接分享页。这两个入口不附带 JPEG，也不先调用系统分享。网页游戏链接取当前 origin + pathname（不含查询参数和锚点），原生桌面使用正式游戏地址。

网页「保存」直接下载原尺寸 JPEG，文件去向由浏览器下载设置决定；不再展示长按原图、二次预览或无法分享图片页面。原生桌面仍弹出保存位置对话框。Instagram、TikTok、Kakao 按钮使用系统分享面板，由用户选择对应应用（网页无法指定目标应用）；通过 `navigator.canShare({files})` / `navigator.share` 分享 JPEG；要求浏览器支持、安全上下文和用户触发。不支持或调用失败时，仅在现有弹窗显示简短状态文字，用户取消时不跳转、不下载。桌面原生未集成系统分享时提示使用保存。不集成各平台自动发布或原生移动相册插件。手机浏览器行为仍需真机复测。

浏览器桥接逻辑可用 `node tests/scene_capture_bridge_test.cjs` 测试（模拟浏览器能力，不替代真机测试）。验证包含分辨率限制、真实 3D 截图无 UI、JPEG 解码/尺寸、桌面文件写入字节一致性及弹窗输入遮挡；图形回归生成 `/tmp/nienie-scene-only.png` 和 `/tmp/nienie-scene-capture-modal.png`。


## 中日文本地化

`LocaleManager`（`scripts/locale_manager.gd`）作为 Autoload，在界面创建前注册 Godot Translation 文案并选择语言。仅中文环境在首页右上角和参数面板顶部提供语言选择：中文 / 日本語，直接显示当前语言。桌面读取系统语言，Web 优先读取浏览器 `navigator.language`：中文环境首次使用中文，允许手动切换并保存在 `user://language.cfg`；其他语言环境统一显示日文、隐藏语言选择，忽略以前保存的中文选择。切换时原地刷新文案与字体，保留当前手感参数、涂鸦和镜头状态。

中文原文作为翻译键，日文集中在 `locales/ja.json`。界面统一通过 `tr()` 获取文案，动态数字先翻译模板再格式化。覆盖首页手感与商品描述、参数、涂鸦、贴纸、拍照保存和分享提示；分享桥接脚本也接收翻译后的文案。所有控件共享 `resources/ui_theme.tres` 全局主题；字体文件仅在该主题中配置，切换字体只需修改这一处，语言切换不会更换字体。`LocaleManager.ui_font()` 为主字体补充 `GenRyuMin2TW-SB.otf` 中文缺字回退及 Godot 默认字体回退：优先保持当前日文字形，缺字才使用后备字体。中文字体随 Web 包导出，不依赖浏览器或手机的系统字体。

`tests/localization_test.gd` 检查语言匹配、回退、两种语言的界面及文案表。`tests/deformation_test.gd -- --japanese` 可运行日文界面的完整交互回归；`node tests/scene_capture_bridge_test.cjs` 验证分享文案与渠道行为。

## 首页与手感预设

游戏页主要布局在 `scenes/game.tscn`，行为绑定在 `scripts/game_screen.gd`，可在编辑器调整顶部返回、手感名称、声音，中部相机、挤压、扭转，以及底部捏捏/涂鸦切换。图片使用 `res/ui/game`，声音按钮沿用首页素材。返回、相机和声音按钮挂载 `PressAnimation`。手感名称为 Label，不可点击；模型只在首页选择。底部模式切换保留既有涂鸦功能和退出视角恢复，参数弹窗及涂鸦工具仍由现有脚本生成，小型参数入口继续保留。

按钮按压动画组件为 `scripts/button_press_animation.gd`：在任意 `BaseButton` 下添加 Node 并挂载该脚本即可复用，不占用按钮自身的脚本位置。进入场景时记录原始缩放，以中心为轴，按下在0.08秒内变为原始缩放的1.05倍，松开在0.12秒内恢复；隐藏或窗口失焦也会恢复，连续点击不累积缩放。倍率与时长可在检查器调整。首页声音按钮、开始按钮已添加 `PressAnimation` 子节点。

模型默认角度在 `scripts/model_profiles.gd` 按资源路径独立配置。当前 `res://glb/sfl.glb` 绕 Y 轴旋转180度，未配置的其他模型偏移为0度。该角度在导入坐标烘焙后应用，并作为返回首页时的默认恢复角度。

启动进入首页，展示当前捏捏产品、四种手感选择、描述、星级和对应商品。首页隐藏参数、涂鸦、拍照、挤压和扭转操作，并在鼠标/触摸输入入口屏蔽按压、拉伸和旋转。点击「开始捏它」进入交互页；「首页」按钮返回选择页并取消当前动作。四种手感独立绑定模型：水润嫩滑→`fy.glb`，绵密泥感→`sfl.glb`，紧实弹韧→`df.glb`，绵密黄油感→`tofu.glb`。对应关系在 `scripts/feel_presets.gd` 的 `MODELS` 中配置。切换产品时重建拾取与形变数据，并清空旧模型的涂鸦/贴纸，避免不同UV之间错贴。首页保留原始产品镜头大小；进入游戏通过 0.3 秒缓入缓出的拉近动画，将相机到观察点的距离缩短为首页的 1/1.2，使产品约放大20%。按压/拉伸镜头、挤压/扭转抬升视角及涂鸦退出恢复均以该游戏距离为基准，返回首页通过0.3秒缓入缓出动画恢复原始镜头和模型默认旋转角度；即使从涂鸦缩放、俯视或抬升动作中返回，也从当前可见镜头平滑过渡，不累积缩放。

预设集中在 `scripts/feel_presets.gd`，首页布局在可直接编辑的 `scenes/home.tscn`，交互逻辑在 `scripts/home_screen.gd`。使用 `res/ui/home` 的现有图片，手感按钮竖排放入滚动区域，默认展示2.5项，上下边缘使用轻量透明渐隐。每项的背景、图标、标题、星级、勾选框和勾均是可编辑节点，只有当前选项显示勾；根节点可调整行高、可见行数和渐隐宽度。声音按钮控制主音轨静音，保留语言选择和开始按钮。水润嫩滑为柔软4/5、回弹3/5，绵密泥感4/5、2/5，紧实弹韧3/5、4/5，绵密黄油感2/5、2/5。星级是产品定位标签，不是物理测量结果。

不同参数单位不直接相加：柔软度评分分别乘以柔软度、下陷深度、拉伸灵敏度和最大拉伸各自的上限；回弹评分分别映射弹性抖动、初始回弹和回弹震动上限，恢复时间反向从4秒映射至0.3秒（回弹越强恢复越快）。例如水润嫩滑为1.28、0.40、2.0、2.88，恢复1.78秒、弹性0.60、初始回弹0.36、回弹震动0.30。参数弹窗同步显示所选预设，可继续调整；重新选择预设会恢复其初始值，不持久化调参结果。握压和扭转也使用手感预设：柔软度4/5、3/5、2/5分别对应原始形变上限的100%、75%、50%，同步控制挤压、鼓出、指印、扭转角度和褶皱幅度；固定手宽、抬升高度和观察角度保持一致。松手后，两种动作共用按当前回弹时长、弹性抖动和初始回弹计算的阻尼弹簧，弹性强的材质回弹更快、往复更明显，泥感和黄油感回弹较慢、振荡较弱。形变仍在GPU执行，仅新增标量参数和弹簧状态计算。

### 蘸蜡碎裂验证模式

捏捏页顶部「碎」（日文「砕」）按钮位于手感名称与声音按钮之间，复用截图按钮底图和点击动画；涂鸦页隐藏。入口可在 `scenes/game.tscn` 编辑，运行逻辑独立在 `scripts/wax_mode.gd`。

进入后临时隐藏底座，程序生成开口透明杯壁、杯口和蜡液体积。拖动模型上下移动控制浸入程度，不显示深度滑条；空白区域上下拖动可翻转、左右拖动可旋转，浸蜡阶段屏蔽捏压与拉伸。翻转绕模型中心，退出模式恢复入场角度。沿水平液面裁切模型表面三角形，累计不同姿态实际浸入的表面区域，提出后蜡膜保留；未浸入时不能开始捏碎。点击「提出并开始捏碎」回到正常操作位置，单指按压、双指拉伸（电脑 Shift＋鼠标）可破坏蜡膜。「重新蘸蜡」重置本轮，碎模式中隐藏顶部「碎」入口与底部捏捏/涂鸦切换，左上角返回按钮清理蜡膜与杯子，恢复底座、位置和捏捏模式；再点击返回才回首页。四个现有产品均可使用。

验证版按表面最远点种子划分72个不规则区域，合并为一个有索引蜡壳网格。每块采样中心及三个相邻位置，复用 `BlobDeformer._target_offset_for()` 计算局部形变梯度，以局部伸缩触发不同阈值的破裂；整体旋转/平移不作为破裂依据。附着部分用局部仿射近似贴合，破裂部分按独立旋转、速度和重力动画脱落，2.5秒后移除；不使用逐片刚体。蜡壳上限24Hz更新，无形变且无下落碎片时停止重建，不改动原模型的形变Shader与法线兼容逻辑。

本版验证深度覆盖、局部碎裂与脱落，尚非完整蜡物理：蜡液面固定水平，支持模型翻转蘸入，单层半透明薄膜，不累计多次厚度；分块边界受源三角网格限制，蜡片无真实体积和碰撞；强形变下附着贴合是近似，脱落动画在模型局部空间。桌面测试约3ms一次蜡壳更新，手机Web仍需真机测试，不代表真机性能结论。

验证：`Godot --headless --path . --script tests/wax_mode_test.gd`；图形运行加 `-- --capture` 可输出浸蜡与碎裂截图到 `/tmp/`。

碎模式不显示浸蜡百分比和底部操作/碎块数量提示。提出后在模型上方显示粉色碎裂进度条和百分比，按本次蜡膜静止表面积加权；全部蜡膜碎裂才显示100%，重新蘸蜡重置进度。

浸蜡界面提供 Clear（奶白）、Pink、Sky、Yellow 四种颜色；选中项以白色外圈标记，切换只改变蜡液颜色，已成形蜡膜保留原色；再次浸入时，仅液面以下区域被新色替换，可同时保留多个颜色。按原三角形裁切不重叠的颜色区域，用顶点颜色在同一个蜡壳网格显示，不叠加额外蜡层。蜡膜不透明度为55%，集中配置在 `WaxMode.WAX_OPACITY`；采用透明深度预通道材质，杯中蜡液保留实体颜色，杯口不染色。提出后隐藏颜色选择，重新蘸蜡保留上次颜色。

蜡膜厚度由 `WAX_THICKNESS_RATIO=0.025`（模型半径比例）统一控制，生成外表面、内表面与分块断口侧壁。脱落时转换为世界坐标独立 RigidBody3D，使用简化凸包、连续碰撞检测及与可见地面同高度的静态碰撞平面；低弹性和摩擦让其落地停留。碎片最多为分块数量（72），不做碎片互撞，重新蘸蜡或退出时清理。此实现替代原先模型局部空间下落动画，实际手机端开销需真机验证。

性能修订：脱落碎片已改为世界坐标的轻量动画，不再创建刚体、凸包或地面物理体。用重力积分、世界Y方向包围盒地面检测、最多两次低幅反弹模拟落地；同时最多18个可见碎片，4秒后回收，超过上限的破损区域仅移除蜡膜而不创建掉落实体。保留真实蜡膜厚度与多色覆盖，附着蜡壳仍为CPU更新，手机真机需继续验证。

蜡膜外观修订：恢复单层薄片，取消内表面与分块侧壁，表面间隙提高到模型半径的1.8%（`WAX_SURFACE_GAP_RATIO`）。完整膜在分块和颜色边界共享光照法线，避免未破裂时预先显露分块线；脱落仍使用轻量动画。

碎裂阶段交互已改为单指/鼠标左键拖动模型产生弯曲与扭曲，上下拖动弯曲、左右拖动叠加扭转，松开缓和复原；不再进入普通按压、双指拉伸或Shift拉伸。空白拖动仍旋转。CPU蜡膜局部应变与模型GPU形变使用同一弯扭公式。

碎片保留修订：大碎片落地后停留到退出碎模式或重新蘸蜡，不再按时间消失。碎裂时向外、向上抛出，以世界重力形成抛物线；使用模型当前形变采样包围盒加碎片半径避让，属于保守近似，贴近模型处可能被推向外侧。每次破裂散出8个白色碎点，MultiMesh对象池最多240个；满池优先覆盖最早落地项，全部在飞行时才覆盖最旧飞行项。白点落地保留，退出/重新蘸蜡统一清空。全部静止后停止动画更新。

碎裂拖动修订：抓取命中的表面点，固定相机朝向拖动平面，将手指屏幕位移转换为模型局部位移。抓点位移最大，周围按平滑距离权重跟随，两端均可拉动；取消固定端点的整体弯曲/自动扭转。松手恢复，普通捏捏模式不受影响。

渐进碎裂：每块记录不可逆损伤，每次抓取仅累积新的峰值形变；每轮上限约22%～34%，持住与回弹不加损伤。较大拉动约3～5轮后陆续脱落。当前应变产生可恢复发白，历史损伤留下白色，25%损伤后逐步打开裂缝，断口距离权重控制白边；完整状态无预设白边。分块现使用 Voronoi 分区平面实际裁切表面三角形，消除沿原三角网格分组产生的阶梯状边缘；当前为分区裁切轮廓，尚非圆润有机断口。

白边性能修订：蘸蜡和提出阶段不计算断口白边。揉捏时仅将超过局部受力阈值的碎块加入队列，每帧最多处理64个顶点，并检查约700微秒的时间预算；完成后缓存边界距离权重，通过0.2秒渐显避免分批计算产生扫线。白边强度随累计损伤/裂缝扩大而增强，脱落保留当前已显示白边。蘸蜡更新上限12Hz，复用未改变的分块数据；首次分区按模型缓存。桌面豆腐测试连续蘸蜡重建约32ms，仍非手机帧率保证，需真机验证。回归脚本：`tests/wax_progressive_edges_test.gd`。

局部裂缝修订：每次抓取最多推进3条共享分区边界（`MAX_CRACKS_PER_GESTURE`），优先受力较大处，同次持住不重复累加。裂缝记录独立于碎块损伤；仅已激活边界局部收缩、发白，不再整块缩小。完整边界使用逐顶点相同的抓取位移保持贴合，避免局部仿射近似造成全片缝隙。各边打开且损伤达到上限后才脱落。碎片外抛速度降低至0.12～0.22、向上初速0.15～0.28，并缩小避让余量；仍为轻量包围盒近似，不是真实碰撞。

蜡膜同步修订：附着蜡膜使用 `shaders/wax_shell.gdshader`，与模型在同一帧接收相同 wax_anchor / wax_bend / model_radius，GPU执行相同高斯抓取位移，并同步修正法线。CPU网格保留静止坐标及裂口偏移，24Hz仅处理损伤、颜色和拓扑变化，不再以24Hz烘焙形变位置；掉落实体继续使用独立材质，避免二次形变。回归覆盖低于网格更新间隔时参数已同步、网格未重建；桌面Compatibility图形绘制验证通过，手机仍需实测。

碎模式形变上限：`BlobDeformer.WAX_MAX_DRAG_RADIUS_RATIO = 0.55`，将抓点最大位移限制为模型半径的55%（原150%）。输入目标和形变提交入口双重限制，模型与蜡膜共用受限参数。裂缝受力值按原幅度补偿，保持逐边开裂能力，不改变每次最多3条的限制。

受力发白外观：静止蜡膜不透明度仍为55%，受力/累计损伤/裂缝白边将颜色渐变为浅灰白 `#e9e9e5`，同时提高不透明度，最高96%。顶点alpha存储绝对不透明度，附着Shader与脱落材质均直接使用，避免再乘55%导致发白处仍透出模型底色。

形变幅度调整：碎模式最大抓点位移由半径55%提高20%至66%（`WAX_MAX_DRAG_RADIUS_RATIO = 0.66`），受力补偿同步调整，每次最多3条裂缝的限制保持。

连续发白修订：附着蜡膜在fragment Shader中用静止表面坐标及当前高斯抓取位移梯度计算连续受力值，发白/不透明度不再读取碎块统一strain或damage。无形变时受力发白消退，仅已打开的裂口保留局部白边。脱落时按顶点采样相同连续场烘焙颜色。电脑与手机使用同一策略；动态裂缝局部切割、分帧与数量上限属于后续步骤，本次保留既有分块拓扑。

### 动态裂缝版本（替代前述预分块流程）
蘸蜡只裁切液面覆盖并生成连续蜡膜，不建立Voronoi种子/碎块。`scripts/wax_crack_growth.gd` 在首次实际受力后分帧焊接表面连接图，按局部应变选择裂缝起点，随后沿表面边、参考拉伸方向逐段延伸，跨多次抓取生长、分叉及连接。裂缝闭合后，分帧遍历三角形连通性，仅切出被隔离的小区域（最多192面）生成脱落网格；其余仍为连续蜡膜。断口沿输入三角网格，尚不是任意曲线重三角化，因此低密度网格仍会限制轮廓精细度。
电脑/手机同策略：连接建立、起点搜索、连通遍历每帧最多96项并检查900微秒预算；每次抓取最多延伸3段，总裂缝最多96段、实体碎片最多18个。达到本轮上限后停止新增，可重新蘸蜡重置。裂缝以Shader局部细缝与白边显示，逐帧拖动仅更新GPU参数，闭合脱落时才更新剩余膜索引；连续发白保留。当前是表面连接图局部切割验证版，CPU预算不包含网格上传/GPU绘制，手机仍需真机测帧率。测试：`tests/wax_dynamic_cracks_test.gd`（连续膜、延迟建立、3段/96段/18片上限、闭合脱落、无需逐帧重建及重置）。

裂缝尺度/圆角调整：每次最多8段（原3段），总96段及18片限制保留。路径至少间隔12个节点才允许闭合（原4个），第12节点后才倾向回接；分叉降低频率，面积小于半径平方0.006的孤立碎屑不脱落，单片最多384面。碎片边界按邻接点在切平面内平滑40%，位移封顶半径2.5%，减少尖角；裂缝显示采用有轻微弓形偏移的路径，避免完全笔直。此为网格轮廓平滑，未增加重三角化，粗网格仍存在折线限制。回归包含最小脱落面积及8段上限。

大块先生成版本：碎模式拉伸时最多新增2个局部区域，使用模型半径0.42倍的圆润不规则16边截面（目标宽度约直径42%），沿表面局部深度范围裁切，保留颜色与插值法线；不依赖原网格寻找小闭环。新区域当次不显裂缝，后续每次抓取最多累积34%边界开裂进度，沿排序后的轮廓逐段打开，完整边界显示后才脱落。切割/搜索与边界收集分帧，每帧48项、900微秒检查；总区域18个、显示裂缝96段，脱落释放裂缝显示容量。此为局部平面裁切近似，曲率大或薄模型侧面仍需验证，网格提交/轮廓排序不计入软时间预算。

开裂节奏加快：每次最多新增6块；新块完成局部切割/边界准备后允许在当次受力中开裂。已有区域的受力推进不再被新区域切割队列暂停，门槛由0.06降到0.025，单次峰值损伤上限由34%提高至62%（保持持住不重复累加）。较强连续抓取回归在3轮内出现脱落；轻拉及新区域分帧准备仍会影响实际等待。

碎裂阻塞修复：搜索游标跨短抓取保留，避免不断重置导致永远无法完成选区；取消整圈裂缝显示额度预留，损伤/脱落与96段Shader容量解耦，显示容量按活跃区域分摊（超出时抽样显示边界）。持住峰值不变时不重复上传。新增 `tests/wax_short_drag_test.gd`，模拟30帧拉动/30帧释放，验证连续短拉仍能生成及脱落。

多块开裂节奏修正：有效抓取提交最多6块的区域生成批次，松手后仍分帧完成；选区间距降低，允许同一受力范围形成多块。新区域完成后显示18%局部裂缝；每次新峰值损伤最多36%，至少3次独立受力才可脱落，持住不重复计数。同次处理全部符合条件的区域，支持多块同时掉落。回归覆盖首次多区域、前两次不掉落、单次多片脱落及短拉释放。

多块可见性/局部裁切修复：单块目标半径由模型半径0.42改为0.26；选区优先相机可见的受力表面，减少背面块。裁切先排除完全位于任一裁切平面外的三角形，直接保留原三角形，避免无关区域被反复细分拖慢后续碎块。舒芙蕾回归验证计数与独立掉落实体一一对应，20轮30帧拉/30帧松短操作出现多个实体；不等于手机实时帧率验证。

方向性裂缝修订：碎模式不再使用圆形裁切区。每次抓取按拉伸向量在局部表面切平面中定短轴，垂直方向定长轴，生成较窄的带状蜡片；新片优先在相机可见受力面上、围绕抓取点的多个目标位置分布。边界首次显示从与拉伸垂直的长边开始，再沿轮廓推进。横向拉伸主要产生竖向裂缝，纵向拉伸主要产生横向裂缝。仍为局部平面近似，强曲率处的裂缝会沿表面弯折；单次最多6块、总18块及分帧预算不变。

首次拉伸全膜分块版本（替代上段逐次局部选区）：蘸蜡结束仍是一张连续膜。首次有效拉伸记录抓取点和方向，立即显示3道横跨拉伸方向的短裂纹；随后以相同的1100微秒/帧软预算、最多96个三角形/帧的裁切预算，选择64个表面种子并按拉伸方向加权的Voronoi距离分割整张膜。分块期间保持原连续膜显示，完成后一次切换为贴合的64块；用户松手时也继续生成，首次受力会在分块完成时补计。之后每次抓取最多让8块受力碎片出现/延长垂直于当次拉伸方向的裂缝，至少3次受力且损伤足够才脱落；最多64个轻量掉落实体，落地保留至重蘸或退出。仅少数受力块显示裂缝，完整块之间不预先显线。全局分块轮廓由首次拉伸方向确定，已有块上的裂缝方向随当次拉伸更新。测试：`tests/wax_dynamic_cracks_test.gd`、`tests/wax_short_drag_test.gd`、`tests/wax_partition_models_test.gd`。

碎裂可见性修订：裂缝 Shader 参数改为局部切割平面的原点、法线和作用半径，利用平面与蜡膜曲面的交线显示连续裂口，替代三角网格短边及空间弦线。作用半径随碎块损伤扩大，保留轻微波动与白边。每块至少5次有效受力，且首次建立裂缝后至少跨过2次抓取才可脱落；每次抓取最多脱落3块。裂缝仍限制96个局部区域。此修订尚未完成 Godot 引擎运行和手机图形验证。

全局裂纹网络修订：首次有效受力后的分块完成时，每个未脱落区域生成一个表面起始裂纹，显示扩展独立于局部掉块损伤；后续抓取扩大覆盖并增加分布于全膜的次级分支。起点投到真实蜡膜顶点，倾角、长度及双频弯曲使用固定空间变化，避免三条等距平行线。主裂纹最多64个、分支补至96个，总上限保持不变。尚待引擎及手机视觉验证。

裂纹时序修复：分块等待阶段每次有效抓取立即追加4个预览裂缝区域，仅保留最新抓取用于完成后的首次损伤，不再积压并在同帧回放所有历史抓取。预览裂缝在切换后保留前32个；每次抓取逐步激活最多6个全局区域及最多8个局部受力区域，取消一次激活全膜。疲劳仅按实际新抓取逐次累计。尚待Godot运行验证。

碎裂轮廓与联动修订：完成分区后，Shader 直接使用CPU裁切相同的种子及方向加权距离，显示最近两分区的共享边界，不再显示彼此独立的切割平面与分支；边界随损伤分段展开。受力选区按抓取侧/对侧各最多4块分配。碎模式拖动增加对侧30%径向联动，拉出时横向收缩、内压时横向扩张；CPU拾取、模型Shader、蜡膜Shader使用相同位移，蜡膜法线通过位移差分更新。尚未进行Godot运行或手机性能验证。

统一裂缝来源修复：删除分块前临时裂缝、独立切割平面、分支及其Shader回退路径。裂缝只通过最终不可变分区的共享边界呈现，实际掉块使用同一分区；脱落要求该块network_progress至少0.95。分块完成前仅显示连续膜和受力发白，不再伪造不对应碎块的裂缝。分块准备等待仍存在，需后续性能验证。

持续受力修订：以传入delta按20Hz累计幅度、方向变化和持续时间，松手停止累计；不再使用固定抓取次数门槛。首次受力用最多512个候选点建立固定64种子，立即供Shader使用，实际三角形裁切继续分帧完成；完成时不更换种子或重置损伤。非均匀间距及3.0方向加权提高大小差异与横向断裂倾向。释放需裂纹充分展开且有可见阶段，网格就绪后设0.6秒释放缓冲、批次0.3秒间隔。新回归tests/wax_continuous_load_test.gd尚未在引擎运行。旧按次数测试不再代表当前行为。

局部受力与回弹脱落调整：抓取影响半径由0.85R降为0.45R，按所在面朝向衰减，对侧最低6%，取消镜像等强受力；裂纹增长系数1.8降为0.85。裂纹成型时仅抽样一次：45%当次回弹、35%再一次有效拉伸、20%再两次有效拉伸后掉落；等待次数只由实际受力的抓取递减，松手后延迟0.06–0.28秒分批掉落，不再要求另一套疲劳值满格。测试脚本已更新，尚未引擎运行验证。

成型脱落修复：完成阈值从0.95对齐Shader完整显缝阈值0.83；去掉仅松手才执行掉落队列的限制。成型时45%在0.12–0.35秒内脱落，其余保留1–2次有效回弹提前脱落，并以1.2–2.4秒真实累计时间兜底（若网格裁切未完成，需等待其完成）。不再因后续抓取未命中同块而永久挂住。尚待引擎验证。

掉落堆积修复：网格未就绪时将裂纹进度限制为0.55，避免显示完整断口却无法掉落；超时仅在网格就绪后累计。释放改为全局每0.14–0.24秒最多1块，不再每帧3块。Shader按当前所属块损伤显示，避免邻块较高损伤提前绘出该块完整断口。注意全膜裁切等待仍未消除；本修订解决表现与队列堆积，不代表裁切性能已经优化。

撤销0.55准备期裂纹上限，允许持续受力形成完整断口。裁切优化：缓存输入顶点所属单元，三顶点属于同一凸Voronoi单元时直接归入碎块；跨单元三角形才裁切，分割平面预计算复用。保持1100微秒软预算及掉落间隔。随机凸组合数值检查通过，尚未完成Godot运行与性能测量。

回弹疲劳：先更新当帧实际形变再计算损伤；松手后继续采样回弹，接近静止后停止。每帧按半径归一化形变速度累计，20Hz结算，附加项为0.10v+0.035v²，v上限6，快速相同位移造成更高疲劳。新抓取重置采样，避免将锚点重设当作冲击。维持拉伸仍按幅度持续累计；回弹中刚成型且抽到立即掉落的块可直接进入短延迟队列。尚待Godot运行验证。

碎块耐受度分层：每次分块随机打乱并固定约30%易碎块（64块中19块），耐受系数0.28–0.48；其余0.85–2.10，分块后不重复抽样。易碎块成型后80%当次短延迟释放、20%再一次有效回弹释放，保留时间兜底及全局掉落间隔。裂纹增长独立乘1.5，即速度提高50%。两三次拉动掉落是调参目标，实际仍取决于幅度、速度、受力位置及网格就绪时间，尚待真机验证。
