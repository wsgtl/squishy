# 捏捏实验室（Godot Web 原型）

这是一个 Godot 4.7 的 Web 捏捏原型，当前加载 `glb/sfl.glb` 正式月饼模型。按压产生局部凹陷，拖动产生大范围拉长与横向收缩，松手后阻尼弹簧恢复形状。

## 运行与操作

- 使用 Godot 4.7 打开 `project.godot`，按 F5 运行。
- 鼠标左键或单指按住、拖动模型：仅按压 / 推揉，凹陷平滑跟随。按住约 1.5 秒逐渐压到最大深度，同时整体轻微压扁、向两侧扩展。
- 电脑端仅 Shift + 左键拖动触发拉伸；松开 Shift 停止拉伸，右键不触发拉伸。
- 触屏在模型上放下两指并向外分开：拉伸。两指一起平移不拉伸，任意一指抬起后恢复单指按压。
- 拉出模型轮廓后仍可继续拖动；支持上下、左右方向。
- 松开后自动回弹；拖动空白处旋转模型。
- 左上角“参数”调整按压深度、手指宽度、柔软度、回弹和拉伸。
- 镜头随拉伸幅度退让；“镜头后退”设为 0 可关闭。

## Web 导出

1. 在 Godot 的“项目 > 导出”中确认已安装对应版本的 Web Export Templates。
2. 选择 `Web` 预设并导出。预设输出路径是 `output/web/nienie.html`。
3. 将导出的整个 `output/web/` 目录部署到支持静态文件的 HTTPS 网站，或用本地 HTTP 服务器预览。不要用 `file://` 直接打开 HTML；浏览器需要通过 HTTP(S) 加载 WASM、PCK 和工作线程文件。

导出预设位于 `export_presets.cfg`。浏览器部署需提供 Godot Web 导出所需的 MIME 类型；启用线程导出时还需服务器设置 COOP/COEP 跨源隔离响应头。本项目默认关闭线程支持，通常不需要这组隔离头。

## 目录与文件

```text
.
├── project.godot           # 项目入口、窗口尺寸、输入与渲染/物理设置
├── export_presets.cfg      # Web 平台导出预设和导出目标
├── icon.svg                # Godot 项目图标
├── scenes/
│   └── main.tscn            # 主场景；挂载主控制脚本
├── scripts/
│   ├── main.gd              # 场景搭建、镜头灯光、输入拾取和 HUD
│   ├── blob_deformer.gd     # 网格拾取、弹簧形变场和法线更新
│   └── doodle_canvas.gd     # 涂鸦纹理、画笔与橡皮擦
└── output/web/              # Web 导出产物（HTML/JS/WASM/PCK）
```

`.godot/` 是编辑器导入缓存，`.uid` 是 Godot 脚本资源标识；它们由 Godot 管理，不是手写的游戏逻辑。`output/web/` 中若已有导出文件，它们是构建产物，重新导出会覆盖对应文件。

## 形变实现

1. **真实表面拾取**：按下时射线与当前变形后的三角面相交，返回命中位置、静止形状中的重心插值位置和法线。计算先按模型半径归一化，避免小尺寸 GLB 受几何精度阈值影响。旧碰撞体不再参与交互拾取。
2. **稳定拖拽**：按压拖动使用静止表面的原生 TriangleMesh BVH，冻结交互相机投影，不追逐变形中的凹面；接触位置和法线以约 45ms 时间常数平滑跟随。系统输入合并为每个物理帧最多一次查询。拉伸使用经过命中点、平行台面的水平面；前后和左右拖动都保持在 XZ 平面，避免俯视镜头把前向拖动映射成向下拉。
3. **按压**：接触法线方向下陷，切平面高斯权重形成碗状凹陷，外围轻微隆起。按住时长通过 smoothstep 渐进增加深度，`press_duration` 默认 1.5 秒，拖动不重置计时。`squash_strength` 默认 0.10，以底面为基准轻微压扁，并横向扩展。最大深度有上限。底部采用平滑压缩，保留至少原始局部高度的 15%，不再把上下面硬压到同一高度。拉伸厚度以底面为基准变化，模型与底座保留最长边 0.15% 的微小间隙，减少深度冲突。
4. **拉伸**：大范围沿拖动方向伸长，垂直方向按伸长倍率平方根的倒数收缩，叠加宽范围的抓取权重。大幅拉伸时应变逐渐集中到中段，形成中间细、两端宽的收腰；横截面比例保留至少 16%，不会主动断开。拉伸上限按模型半径计量。该收缩是视觉近似，不是完整体积约束。
5. **回弹**：对形变场的强度和拉伸向量积分，使用最多 1/120 秒的子步。拉伸释放时固定原拉伸轴并保留正负位移：正向变长变薄，负向越过原形后变短变厚。拉伸采用较低阻尼，`recovery_time` 内约三个振荡周期，各次回弹逐渐衰减；释放时实际拉伸越长，回弹越强。负向压缩倍率保持正值，避免模型翻转。相同位置始终得到相同位移，避免独立顶点弹簧撕开 UV 接缝。重新抓取时保留回弹状态，按压接触位置及时更新。静止后停止计算。
6. **渲染**：静态网格配合 `shaders/soft_deformation.gdshader`，GPU 计算顶点形变和有限差分法线。逐帧 CPU 只更新弹簧和 uniform，不再重建网格或上传全部顶点。保留本项目模型的底色贴图、颜色、粗糙度、金属度和法线贴图；形变时同时变换法线贴图的切线基。首次／重新抓取才按需生成当前形状的 CPU 拾取数据；拖动期间复用静止表面 BVH。GPU 与按需 CPU 求值采用相同形变公式。

主要文件：`scripts/main.gd` 负责输入、相机和 HUD；`scripts/blob_deformer.gd` 负责拾取和弹簧状态；`shaders/soft_deformation.gdshader` 负责 GPU 形变和法线。

当前支持单指按压、双指拉伸和模型的第一个 MeshInstance / surface；正式月饼模型为单网格、单 surface（5,925 个顶点）。加载时将 GLB 节点的旋转、缩放烘焙到顶点、法线和切线，统一为直立坐标，再按最长边归一化、保留建模师设置的原点和水平位置，只调整高度放在底座上。没有自碰撞、刚体交互或严格体积保持。复杂多部件模型的大幅形变仍可能出现局部穿插，移动浏览器性能需要在目标设备上实测。

```sh
godot --headless --path . --script tests/performance_test.gd
```

验证真实模型拾取、鼠标及触屏事件、轮廓外拖动、竖直拉伸、GUI 捕获、镜头稳定性、回弹和参数极值。图形环境可追加 `-- --capture`，保存静止、按压、拉伸和恢复截图到 `/tmp/nienie-*.png`。

### 性能对比

本机 Apple M4、Godot 4.7.2 headless，每项 120 次采样的 CPU 中位耗时（不是手机 FPS，也不包含 GPU 绘制）：

| 工作 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 按压状态更新 | 3.550 ms | 约 0.001 ms |
| 拖动输入及拾取 | 0.962 ms | 0.009 ms |
| 拉伸状态更新 | 5.719 ms | 约 0.001 ms |

首次抓取／重新抓取仍有一次 CPU 形状求值和 BVH 建立成本。手机浏览器 GPU 帧耗时及触摸延迟需要真机验证。

### 按压轨迹与边缘过渡

默认手指宽度从 0.23 缩小 40% 至 0.138，参数面板同步调整。每次按压沿用触下时的法线方向，避免顶部与侧面法线切换导致突然塌陷。当前接触位置在本次物理更新中直接跟随拾取点，不再按半径限速或缓慢追赶；触下立即施加基础压力，继续按住仍会逐渐加深。

拖动轨迹采用连续线段的扫掠凹槽，保留 12 段常规轨迹和最多 8 段渐隐轨迹，直线拖动合并延长，转弯新增线段。沿线段插值两端深度并按回弹时长指数衰减，消除独立圆坑叠成的分节外观；不同按压手势不连接。使用按形变强度加权的连续归一化混合，避免硬切换造成法线亮点，也不累加压深。凹坑深度同时受参数、模型在按压方向的厚度 45% 和接触半径 1.5 倍限制。整体压缩采用独立的 0.25 秒时间常数渐进跟随，触下基础压力只立即作用于局部凹坑。历史轨迹与当前凹陷使用相同 GPU 和 CPU 公式，全部恢复后停止更新。容量满后旧轨迹进入渐隐槽位，在回弹时长的 35% 内平滑淡出，完全消失后才删除；新增转弯段按回弹时长的 1/16 节流，当前接触点仍逐帧跟手。轨迹增加 GPU 顶点计算，目标手机仍需真机评估。

恢复末段按每个求值位置的局部最大位移归一化混合权重，避免远处仍在按压的强接触点影响旧痕迹消退。历史轨迹不再按单独强度阈值停算；按压和轨迹强度都低于 0.00001 后才整体清理。

### 粉色柔光场景

`shaders/pink_backdrop.gdshader` 在地面上绘制浅粉渐变、奶白椭圆柔光及底座接触阴影；背景不受模型灯光影响，不使用实时反射或额外阴影贴图。柔光固定在画面中，接触阴影使用世界坐标并跟随底座尺寸。底座保留 bottom.glb 原有材质与木纹颜色，不额外提亮。相机以约 60° 仰角俯视模型，左上方主光配合弱补光，使投影落向画面右下方；月饼保留形变材质。背景使用 unshaded 保持移动 Web 上的稳定外观。

拉伸渲染优化：法线与法线贴图共用切线方向的有限差分采样，完整形变求值由每顶点 5 次降至 3 次（使用法线贴图时），保持切线手性；拉伸倍率、收腰强度和轴向范围在 CPU 每帧计算后上传。无按压时跳过当前凹坑的指数计算。压缩回弹的高度膨胀幅度增强为原增量的 1.75 倍，厚度以底面为基准向上变化，并乘以 X/Z 两方向的余弦平方包络：中心最高、边缘回到原高度，边缘斜率为零，避免整体一起拔高。GPU 实际帧率需要目标手机实测。

### 按压手感切换

参数面板中的“按压收拢与翘边”开关默认开启：中心凹陷、周围材料沿切平面向按压点收拢，侧缘平滑向上卷成圆弧，随按压强度及轨迹恢复变化；关闭使用原版高斯碗状按压公式。代码默认值由 `scripts/blob_deformer.gd` 的 `DEFAULT_RAISED_RIM_PRESS` 控制。切换时结束当前手势并清除残余形变，防止已有轨迹突然改变轮廓。新模式是收拢与侧边弯曲的视觉近似，不是严格体积守恒求解；沿用原深度限制和底面保护。CPU 拾取镜像与 GPU 使用相同轮廓。

收拢模式的拖尾恢复时间为原版的 30%，松手后局部按压弹簧恢复也加快；拉伸振荡周期与原版拖尾保持不变。

双指拉伸在开始时记录两个材料接触点，并分别施加浅凹陷；抓取压力渐进建立，松手后衰减。Shift 鼠标拉伸使用鼠标抓点及其对侧支撑点。接触凹坑沿用原底面保护，重叠时只取较强凹陷避免加倍压深，拉伸期间无需逐帧重新拾取。

按压释放附加小幅方向回弹：沿最后按压拖动的水平轴，原地按压默认模型 X 轴，以速度脉冲启动缩短增厚，再反向回摆并衰减。幅度随释放时压力增强，两种按压模式均生效；沿用拉伸的底面固定增厚与中心隆起公式，不改变拉伸释放参数。


## 涂鸦

### 进入与操作

点击左上角「涂鸦」直接进入绘制模式，显示两侧工具栏，不打开全屏弹窗。进入时清除模型当前形变；在模型上用鼠标左键或单指点击、滑动即可绘制，绘制手势不触发按压或拉伸。拖动空白处可以左右旋转模型。

| 控件 | 当前行为 |
| --- | --- |
| 左侧橡皮擦开关 | 开启后局部擦除涂鸦，露出模型原有颜色和纹理；关闭后恢复画笔。擦除时禁用选色按钮。 |
| 左侧竖向粗细条 | 范围为 2–48，单位为 UV 纹理像素直径。画笔默认 10，橡皮擦默认 30；两者分别记住粗细，切换时自动恢复。 |
| 左下颜色按钮 | 打开精简选色面板，改变后续绘制的颜色与不透明度。 |
| 左下「清空」 | 清空整张涂鸦层，保留模型原材质。 |
| 右侧「缩放／视角」按钮 | 切换同一根竖条的功能，切换时分别保留当前缩放倍率和相机角度。 |
| 右侧竖条：缩放模式 | 范围 60%–200%，向上放大、向下缩小。通过相机距离控制显示大小，不改变模型尺寸或 UV。 |
| 右侧竖条：视角模式 | 向上到 90° 正俯视，向下到 0° 平视。 |
| 右上眼睛按钮 | 将两侧涂鸦工具栏降至 20% 不透明度，并禁止工具栏点击、拖动与键盘聚焦；手势可穿透到模型。眼睛按钮仍可用，再次点击恢复显示与操作。 |
| 顶部「退出涂鸦」 | 隐藏工具栏并恢复捏压交互；相机角度和缩放用约 0.55 秒缓入缓出动画恢复默认视角与 100% 缩放。 |

两侧工具栏靠屏幕边缘排列，粗细条与缩放／视角条没有白色背景底板。底部没有左右旋转滑条，旋转通过拖动空白处完成。退出涂鸦后笔迹仍保留，随按压、拉伸和回弹一起形变。打开「参数」弹窗也会退出涂鸦并触发视角恢复。

### 选色与透明度

选色面板使用精简后的 Godot `ColorPicker`，保留大正方形选色区、色相条及 R/G/B/A 四条滑杆。R/G/B 控制颜色，A 控制画笔不透明度：0 完全透明，255 完全不透明。字体、滑杆与数值输入区域已放大，隐藏吸管、颜色模式切换、Hex、预设和历史颜色。

新颜色可以覆盖已有笔迹；半透明画笔采用颜色叠加，重复描画会逐渐加深。橡皮擦直接减少涂鸦层透明度，不使用模型底色覆盖，因此能露出原有纹理。

### 实现与性能

- `scripts/main.gd`：绘制输入、工具栏、精简选色器、相机缩放与角度切换、退出视角过渡。
- `scripts/blob_deformer.gd`：三角形射线拾取，通过重心坐标插值得到命中表面的 UV，并绑定涂鸦纹理。
- `scripts/doodle_canvas.gd`：1024×1024 独立 RGBA `ImageTexture`，实现笔刷颜色混合、局部擦除和清空。
- `shaders/soft_deformation.gdshader`：按 UV 将涂鸦颜色叠加到原材质上，笔迹随网格一起形变。

拖动沿屏幕路径采样，不直接连接 UV 坐标，避免跨 UV 岛产生错误连线。绘制时复用静止表面 BVH，不逐笔重建模型网格；只在涂鸦发生变化时，每个渲染帧最多上传一次纹理。

所有笔迹合并到同一张纹理，不按笔画数量增加模型或绘制对象，因此已有笔迹数量不会持续增加显示开销。单张 RGBA8 像素数据约 4 MiB，CPU 图像与 GPU 纹理分别占用内存，实际总占用还包含运行时开销。绘制时的主要成本是射线拾取、笔刷覆盖像素计算和纹理更新；较粗笔刷及快速拖动会增加计算量。尚未进行手机真机帧率验证。

### 当前限制

当前只维护本次运行中的一张涂鸦层，退出绘制模式不会丢失，重新启动游戏后清空。**保存功能暂不实现**；当前没有多作品存档、恢复或存档选择预览。

笔宽使用 UV 纹理像素单位，不同 UV 密度区域的实际线宽可能不同。重叠 UV 的区域会共享笔迹，正式模型应提供不重叠的 UV。

涂鸦相关回归验证包含鼠标与模拟触摸绘制、UV 落笔、颜色覆盖、不透明度、局部擦除、工具粗细独立记忆、缩放与视角切换、淡化后的输入穿透，以及退出视角过渡。运行方式见上方「验证」；图形测试可生成 `/tmp/nienie-doodle-*.png` 截图。

## 参数弹窗

「参数」入口打开带半透明背景的全屏弹窗，点击内容区外背景或右上角「关闭」即可关闭，内容支持滚动。参数文字已放大加粗，滑动条、拖动圆点和开关使用放大样式。此弹窗用于形变参数调整，与涂鸦模式的两侧工具栏分开。
